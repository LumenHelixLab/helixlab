Why HelixLAB

Research tooling is usually a pile of notebooks, API keys in code, and results nobody can reproduce. HelixLAB treats a research workflow as infrastructure: declared, validated, sandboxed, and auditable.

One lab, every engine

Compose Wolfram, GAP, SageMath, and Qiskit nodes on one canvas. Each runs in a network-isolated sandbox; results merge into a single research memo with citations.

Provider-agnostic LLMs

Tool-calling adapters for OpenAI, Anthropic, Gemini, Kimi, and Llama — one neutral contract. Swap models without touching your lab. No vendor lock-in.

Reproducible by construction

Typed parameters, {{placeholder}} substitution, deterministic execution order, and SHA-pinned inputs. Re-run next year; get the same answer.

Security as a default

Engine code runs in Docker with no network, cgroup CPU/memory caps, read-only filesystems. Secrets live in environment variables — never in prompts or specs.

Evidence, not vibes

Literature nodes query SciSpace, Consensus, and Semantic Scholar alongside computation — the memo shows the math and the papers.

Learns, with a gate

The HESOT feedback loop clusters your corrections and proposes prompt improvements — proposals only. A human approves every change.

Architecture

Four small services over two backing stores. Every arrow is a versioned contract.

The frontend talks REST and WebSocket to an Express API gateway, which dispatches to a FastAPI orchestrator. The orchestrator compiles Lab Specs into a DAG and drives Celery workers running sandboxed math engines, plus a HESOT feedback service. Adapters cover Wolfram, GAP, SageMath, and Qiskit; SciSpace, Consensus, and Semantic Scholar; and OpenAI, Anthropic, Gemini, Kimi, and Llama.

Deterministic core

Lab Specs compile to an execution DAG (Kahn's algorithm, declaration-ordered ties). Cycles, dangling dependencies, and duplicate node ids are hard errors.

Neutral schemas are the contract

Providers never leak past the adapter boundary. schemas/ is versioned; changing it is a migration, not an edit.

Documentation

Everything ships in the repo — this page carries the operating core. The full engineering spec lives at docs/helixlab-spec.md.

Invariants — violating any of these is a bug

  • Provider-agnostic core — no engine or LLM SDK import outside adapter modules.
  • Neutral schemas are the contract — ToolSchema in, LLMResponse out; provider shapes never cross the boundary.
  • Sandboxing — engine code in Docker: --network none, cgroup limits, read-only filesystem.
  • Secrets — environment variables only; never in code, prompts, logs, or Lab Specs.
  • Validation — every Lab Spec and input validated against JSON Schema (injection defense).
  • Claim discipline — node results are {success, output, error}; one retry; HESOT proposes, humans approve.
  • Deterministic artifacts — a run reproduces from (preset, parameters) alone.

Preset format

Presets are JSON files with typed, defaulted parameters. The orchestrator substitutes {{parameter}} placeholders before execution — a run reproduces from (preset, parameters) alone.

{
  "id": "qec_ag_codes",
  "name": "Quantum Error Correction from AG Codes",
  "nodes": [
    { "id": "curve",    "type": "compute", "engine": "sage",
      "code_template": "C = curves.genus({{genus}}).random({{field}})" },
    { "id": "code",     "type": "compute", "engine": "sage",
      "code_template": "GoppaCode(C)", "depends_on": ["curve"] },
    { "id": "simulate", "type": "compute", "engine": "qiskit",
      "params": { "error_model": "depolarizing", "rate": "{{error_rate}}" } },
    { "id": "literature", "type": "literature", "source": "scispace",
      "query": "quantum codes from algebraic curves" },
    { "id": "plot", "type": "visualization", "chart": "error_rate_curve",
      "data_ref": "simulate.output" }
  ],
  "parameters": [
    { "name": "genus", "type": "integer", "default": 3 },
    { "name": "field", "type": "integer", "default": 7 },
    { "name": "error_rate", "type": "float", "default": 0.01 }
  ]
}

Quickstart

From clone to a running lab in four commands. Backing services are Postgres + Redis; everything else is service-local.

# clone + backend services
git clone https://github.com/LumenHelixLab/helixlab && cd helixlab
cp .env.example .env          # add your provider keys (never commit .env)
docker compose -f dev/docker-compose.yml up -d postgres redis

# API gateway (Node, :8080)
pnpm --dir services/api-gateway install
pnpm --dir services/api-gateway start

# orchestrator (Python, :8090)
pip install -r services/orchestrator/requirements.txt
uvicorn services.orchestrator.app.main:app --reload --port 8090

# workers (Celery + Redis)
celery -A services.worker_manager.app.celery_app worker -Q compute -c 2

# verify
curl http://127.0.0.1:8080/api/health
